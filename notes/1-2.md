# 1-2 用 JSON Schema 定義工具：給模型一本「說明書」

> 完成於 commit `f3c5629`。

## 情境

1-1 的模型只會聊天，摸不到你的電腦。要讓它「做事」，第一步不是寫功能，而是**告訴它有哪些工具可以申請**——用一份規格書描述 `list_dir` / `read_file` / `write_file` 三個工具長什麼樣、參數要填什麼。這份規格書跟著每次請求一起送出去。

## 觀念

- **`TOOLS` 只是說明書，不含任何可執行程式**。角色跟 Swagger/OpenAPI 文件一樣：`description` 是寫給模型看的，它靠這段文字決定「什麼時候該用這個工具、參數該填什麼」。描述寫得爛，模型就用得爛。
- **`tool_calls` 是「申請單」**。模型只能「說」它要用工具，真正執行的是你的 Python 程式。對照前端：模型＝前端發 `fetch` 請求，你的函式＝後端。所以**模型的能力上限＝你寫的函式集合**——你沒給刪檔工具，它就永遠刪不了檔。
- **`arguments` 的值不可信**。像 `path` 是模型自己推論出來的，它可能亂填（`../../etc/passwd`）。安全邊界要寫在你的程式裡（Step 2 的主題），不能指望模型自律。
- **prompt injection**：模型讀到的檔案內容可能被它當成指令，跟 XSS/SQLi 是同一家族的問題——資料與指令走同一條通道。差別是 LLM 無法可靠地 escape，只能「圈住傷害」：工具限制在 workspace 內、設步數上限、最小權限。
- 驗證方式：問「列出目前資料夾」，模型回覆的 `content` 是空字串，改回 `tool_calls: [{function: {name: "list_dir", arguments: {path: "."}}}]`——它沒有回答你，它在**遞申請單**。

## 語法逐條（Python ↔ JS）

實際程式（`agent.py`，節錄一個工具）：

```python
TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "read_file",
            "description": "讀取一個文字檔的內容",
            "parameters": {
                "type": "object",
                "properties": {
                    "path": {"type": "string", "description": "要讀取的文件路徑"}
                },
                "required": ["path"],
            },
        },
    },
    # ... list_dir、write_file 同格式
]

def chat(msg):
    body = {"model": MODEL, "messages": msg, "stream": False, "tools": TOOLS}
    # 其餘同 1-1
```

#### list 裡放 dict：跟 JSON 的 array of objects 一樣

Python
```python
TOOLS = [ {...}, {...} ]
```
JS
```js
const TOOLS = [ {...}, {...} ]
```
巢狀 dict（`{"function": {"parameters": {...}}}`）一層層往下，寫法跟 JS 的巢狀 object 幾乎相同，只差 Python 的 key 必加引號；dict 的值也可以是 list（`"required": ["path"]`）。

#### 尾逗號：Python dict ≠ JSON

Python
```python
{
    "required": ["path"],
}
```
JS
```js
{
  required: ["path"],   // JS 也允許尾逗號
}
```
Python 允許（也鼓勵）最後一項留逗號，diff 乾淨；JS 同樣允許；**JSON 不允許**——這是「Python dict 長得像 JSON 但不是 JSON」的差異之一。

#### body 多一個 key，說明書就送出去了

Python
```python
body = {"model": MODEL, "messages": msg, "stream": False, "tools": TOOLS}
```
JS
```js
const body = { model: MODEL, messages: msg, stream: false, tools: TOOLS }
```
dict 的值放變數即可；`tools` 這個 key 跟著每次請求送出，模型才知道有哪些工具可申請。

### 回應格式（模型遞來的申請單）

```python
# result["message"] 長這樣：
{
    "role": "assistant",
    "content": "",
    "tool_calls": [
        {"function": {"name": "list_dir", "arguments": {"path": "."}}}
    ],
}
```

- **`tool_calls` 是 list**：模型可以一次遞好幾張申請單，處理時要用迴圈跑。
- **`arguments` 在 Ollama 已是 dict**：OpenAI API 給的是 JSON **字串**，要自己 `json.loads`——換平台時這裡會咬人。
- **`content` 變空字串**：模型「這回合不說話，只申請工具」的訊號。

## 踩過的坑 / 備註

- Python dict 長得像 JSON 但不是 JSON：`True`/`None` vs `true`/`null`、允許尾逗號、key 可以不是字串。靠 `json.dumps` / `json.loads` 在兩者之間換，對應 `JSON.stringify` / `JSON.parse`。
- `description` 是介面的一部分，不是註解——改了它，模型的行為就會變。
