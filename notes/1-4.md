# 1-4 agent 迴圈：把「手動查表執行」包進 while，agent 就活了

> 完成於 commit `f72b9f0`，Step 1 收官。

## 情境

1-3 結束時，整條鏈其實已經通了，只是每一步都要人手動接：模型遞申請單 → 你查 `TOOL_FUNCTIONS` → 你執行 → 你把結果貼回去。1-4 做的事只有一件——把這段手動流程包進迴圈：

```
組 messages → chat() → append 模型回覆
  → 沒有 tool_calls：印出文字，收工
  → 有 tool_calls：逐張執行，以 role:"tool" 塞回 messages，再送一輪
```

迴圈一包起來，agent 就「活了」：你給一句任務，它自己決定要跑幾輪工具、什麼時候停。

## 觀念

- **role 有三種**：`user`（你說的話）、`assistant`（模型說的話，含申請單）、`tool`（工具執行結果）。工具結果**必須**以 `role: "tool"` 回填——模型下一輪就是靠這個分辨「哪些是事實回報、哪些是自己說過的話」。
- **停止條件是「模型不再申請工具」**。回覆裡沒有 `tool_calls`，代表模型認為做完了、改用文字回報——這也埋下了本階段最重要的發現（見文末「關鍵失敗證據」）。
- **messages 是唯一的狀態**。迴圈每一輪都把整包 messages 重送，模型全靠它知道進度——這就是 1-1 說的「list 是 agent 的全部記憶」在迴圈裡的樣子。

## 語法逐條（Python ↔ JS）

實際程式（`agent.py`）：

```python
def agent(task):
    messages = [{"role": "user", "content": task}]

    while True:
        reply = chat(messages)
        messages.append(reply)

        if "tool_calls" not in reply:
            print(reply["content"])
            break

        for call in reply["tool_calls"]:
            func = call["function"]
            tool_name = func["name"]
            tool_args = func["arguments"]
            result = TOOL_FUNCTIONS[tool_name](**tool_args)
            messages.append({"role": "tool", "content": result})
```

#### append：往 list 尾端加一項

Python
```python
messages.append(reply)
```
JS
```js
messages.push(reply)
```
名字不同、行為相同——都是原地修改（mutate）原本的 list。

#### while True + break：無限迴圈與出口

Python
```python
while True:
    ...
    if 條件:
        break
```
JS
```js
while (true) {
  ...
  if (條件) break
}
```
「跑到某個條件成立才停」的標準寫法。agent 不知道要跑幾輪，所以用無限迴圈、把出口寫在裡面。

#### not in：dict 有沒有這個 key

Python
```python
if "tool_calls" not in reply:
```
JS
```js
if (!("tool_calls" in reply)) {
```
JS 也有 `in`，但否定要在外面包一層 `!(...)`；Python 多了直接可讀的 `not in`，唸出來就是句子。

#### for ... in：逐項走訪 list

Python
```python
for call in reply["tool_calls"]:
```
JS
```js
for (const call of toolCalls) {
```
注意對應關係：Python 的 `for...in` ＝ JS 的 `for...of`（拿**值**）；JS 自己的 `for...in` 是拿 key，別搞混。

#### 巢狀取值：一路中括號

Python
```python
call["function"]["name"]
```
JS
```js
call.function.name
```
1-1 說過 dict 沒有點語法，巢狀就是中括號一路串下去；每一層 key 不存在都會直接 `KeyError`。

#### 縮排即區塊：縮錯＝包錯位置

Python
```python
def chat(msg):
    ...
    def agent(task):   # 多縮 4 格 → 變成 chat 的「區域函式」
        ...            # 外面呼叫 agent() → NameError
```
JS
```js
function chat(msg) { ... }
function agent(task) { ... }   // 區塊靠 {}，縮排只是美觀
```
Python 的縮排**就是**大括號：`def` 多縮一層，整個函式就被包進上一個函式裡，外部看不到。JS 縮排錯了頂多醜，Python 縮排錯了是換了一個意思。

#### 直譯器＋檔案：程式怎麼跑起來

Python
```bash
python3 agent.py
```
JS
```bash
node app.js
```
同一個模式：直譯器讀檔、從上到下執行。頂層的 `def`／`=` 執行到才存在（1-3 的無 hoisting），所以測試碼放最後的 `if __name__ == "__main__":` 裡。

## 踩過的坑（依序）

1. **`def agent` 多縮了 4 格**，整個函式被包進 `chat()` 裡面 → 外面呼叫 `agent()` 直接 NameError。教訓：縮排即大括號，Python 的排版就是語法。
2. **key 打成 `"_tool_calls"`**：不報錯、但行為錯——`"_tool_calls" not in reply` 永遠成立，工具永遠不執行，模型每輪都在空講話。字串 key 沒有拼字檢查，跟 JS 的 `obj.typo` 安靜回 `undefined` 是同一類雷，而且比 KeyError 更難抓（連炸都不炸）。
3. **第一次呼叫 Ollama 像當掉**：其實是冷啟動在載模型進記憶體，等就好。第二次之後就快了。

## 關鍵失敗證據：宣稱完成 ≠ 真的完成

驗收任務：「在 workspace 建 hello.txt，內容寫今天日期」。結果——

- 檔案**有**建立；
- 但內容是字面文字 **`今天是 $(date)`**：模型沒有時鐘、沒有 shell，它「想像」了一個 shell 展開機制，以為 `$(date)` 會被誰代換掉；
- 然後它回報：「**已成功寫入今天的日期**」。

三個事實疊起來的結論：模型的「我做完了」只是它的**信念**，不是事實。停止條件交給模型判斷（沒有 `tool_calls` 就收工）在流程上是對的，但**完成與否的判定權不能給它**——要交給驗證程式實測（讀回檔案、檢查內容）。這就是之後 Step 4（L09/L10 驗證迴圈）的動機；`LEARNING_PLAN.md` 進度節有同一筆紀錄可對照。
